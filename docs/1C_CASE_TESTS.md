# Сценарий тестов кейса «запчасть для техники»

Где что лежит:
- **Сами тесты**: `tests/` (pytest, все внешние зависимости — FakeRequests)
  - `tests/test_onec.py` — генератор BSL и разбор результатов `onec.py`
  - `tests/test_gateway.py` — HTTP-эндпоинты шлюза, чат-сущность, интенты
  - `tests/test_extract_json.py` — извлечение JSON из ответа LLM, build_answer
  - `tests/test_mock_api_contract.py` — контракт mock-api (остатки + заказы)
  - `tests/test_snapshots.py` — снапшоты фразировок (syrupy)
- **Данные**: `fixtures/case-parts/dataset.json` (+ `dataset.md`), созданные
  объекты — `docs/1C_CASE_DATA.md`

Запуск: `.venv\Scripts\python.exe -m pytest -q` (145+ тестов, без GPU/1С/LM).

## 1. Диалог «запчасть для техники» (лестница подтверждений)

Целевой сценарий по комментарию заказчика: система **никогда не принимает
слова на веру** — сверяет с базой и подтверждает. Проверяется живьём
(`/ask-text` с `chat_id`) и юнит-тестами шагов.

| Шаг | Реплика | Интент LLM | Бэкенд | Ответ |
|---|---|---|---|---|
| 1 | «нужен диск» | `clarify` | — | «Для какой техники нужен диск? Назовите марку, модель или госномер.» |
| 2 | «кировец» | `lookup_vehicle` | `onec.find_vehicles` (execute_query) | «Нашёл технику: Трактор Кировец К-744Р. Гос. № А123ВС04 VIN XTA…. Это она?» |
| 3 | «да» | `lookup_parts` | `onec.find_parts` | «Есть варианты запчастей для техники Кировец: …(арт. DK-300)… Какой нужен?» |
| 4 | «задний» | `request_part` | роутинг B1–B4 | «Запчасть есть на складе инженера. Создан заказ на ремонт № …» |

Негативные ветки (тоже часть сценария):
- техника не найдена («камаз») → «…в базе не найдена — такую технику мы
  не обрабатываем. Есть, например: тракторы/погрузчики… Уточните.»
- «нет» на показанную технику → сброс подтверждения → снова `lookup_vehicle`
- запчасть не найдена → «номенклатуры в базе нет — такую запчасть мы
  не обрабатываем. Назовите артикул или другую запчасть.»
- несколько кандидатов → `AMBIG_VEHICLE` («найдено несколько единиц… уточните»)

## 2. Юнит-тесты генераторов BSL (`test_onec.py`)

- `test_build_order_code_shape` — заказ поставщику: однострочные запросы,
  лемматизация, оба количества + упаковка, шапка с последнего заказа
- `test_build_part_request_code_shape` — request_part: однострочные запросы,
  токены независимо (`bsl_literal`), склады кейса, все ветки B1–B4 +
  NO_VEHICLE/NO_PART/AMBIG_VEHICLE, обязательные поля Заказа на ремонт
  (организация/подразделение/вид ремонта/приоритет/статус/операция/даты
  +неделя/строка «Ремонты»/статья расходов ЦУ-000181/вариант обеспечения) и
  ЗаказаНаПеремещение (статус КВыполнению, самовывоз, приёмка, обеспечение)
- `test_token_matchconds_order_insensitive` — «масляный фильтр» находит
  «Фильтр масляный»; режимы кавычек (execute_query vs execute_code)

## 3. Юнит-тесты разбора результатов (`request_part`, фейковый transport)

| Тест | onec_code | Ожидание |
|---|---|---|
| branch1 | `B1\|РЕМ\|Техника\|Товар\|Арт\|N` | branch=B1, docs=[ремонт], «складе инженера» |
| branch2 | `B2\|РЕМ\|ПЕР\|…` | branch=B2, docs=[ремонт, перемещение] |
| branch3 | `B3\|РЕМ\|ЗП\|ПЕР\|…` | branch=B3, docs=[ремонт, заказПерем, перемещение] |
| branch4 | `B4\|ЗАК\|…` | branch=B4, «заказ поставщику» |
| no_vehicle | `NO_VEHICLE\|список` | found=False, подсказка «Уточните» |
| ambiguous | `AMBIG_VEHICLE\|список` | found=False, «несколько единиц техники» |
| no_part | `NO_PART\|…` | found=False, «не найдена» |
| error | `ERROR\|…` | RuntimeError |
