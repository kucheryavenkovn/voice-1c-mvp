# scripts/1c-case — наполнение живой 1С кейсом «запчасть для техники»

Скрипты на языке 1С (BSL), выполняются в базе через MCP Toolkit
`POST /api/execute_code` (обработка `MCP_Toolkit.epf`, порт `6003`).
Данные кейса — [fixtures/case-parts/dataset.json](../../fixtures/case-parts/dataset.json)
(+ человекочитаемый [dataset.md](../../fixtures/case-parts/dataset.md)).

## Индекс скриптов

| Файл | Что делает | Создаёт |
|---|---|---|
| [10_fill_catalogs.bsl](10_fill_catalogs.bsl) | Справочники (идемпотентно, повторный запуск безопасен) | Вид номенклатуры «Запчасти для спецтехники»; склады «Склад инженера / текущего ОП / другого ОП»; 17 позиций номенклатуры по артикулам (DK-300, 12345, DK-100, DK-744-02, 77777 + добор); технику «Кировец К-744Р А123ВС04», «МТЗ-82 В777ОР04» |

```powershell

& .venv\Scripts\python.exe scripts\1c-case\run_bsl.py scripts\1c-case\10_fill_catalogs.bsl
& .venv\Scripts\python.exe scripts\1c-case\run_bsl.py scripts\1c-case\20_fill_purchases.bsl
```

## Особенности реализации (выявлены на живой базе)

- `execute_code` не допускает объявления функций — только линейный код.
- `СтрРазделить` трактует разделитель как **набор символов** (`";;"` давал пустые
  элементы) — пары разделены `~`, внутри `артикул=кол` через `;`.
- В запросах поля через точку требуют алиаса таблицы (`КАК Номенклатура`).
- `ПОДОБНО` нечувствителен к регистру — вид номенклатуры ищется точным `=`.
- Смена вида у существующей номенклатуры требует `ОбменДанными.Загрузка = Истина`.
- В строках документов заполняются **оба** количества + `Упаковка`
  (из `Номенклатура.ЕдиницаИзмерения`) — иначе в ERP количество «не проставляется».
- Чёрный список `execute_code` должен пропускать `Записать` (пользователь ослабил).
